## 三件事在解决不同问题

经常有人说"我们要不要 fine-tune 一下让模型更准"——但他想解决的问题可能根本不是 fine-tune 该上的。

| 技术 | 解决的核心问题 | 不解决什么 |
|---|---|---|
| **Prompting** | 让模型按你的格式 / 风格 / 思路工作 | 模型不知道的事实 |
| **RAG** | 让模型用上你的私有 / 实时知识 | 模型推理能力不够 |
| **Fine-tuning** | 教会模型新行为 / 新格式 / 让它更专业 | 实时事实（fine-tune 不能让模型知道昨天的财报）|

记住这张表，下一次纠结时先问自己：**我要解决的是这三类问题里的哪一类？**

## 决策矩阵

```
要解决的问题
├── 模型不知道你的私有数据 / 实时数据
│       → RAG
│
├── 输出格式 / 风格 / 推理不到位
│       └── 试过 prompt engineering 吗？
│             ├── 没试 → 先写好 prompt（80% 的问题这一步就解决了）
│             └── 试过且不够 → 继续判断
│                   ├── 任务"风格"难用文字描述（比如品牌语气、特定推理风格）
│                   │     且有 1000+ 标注样本 → Fine-tuning
│                   └── 任务有清晰规则 → 加更好的 few-shot examples / CoT
│
└── 模型推理能力不够
        → 换更强的模型，或上 Chain-of-Thought / Reflection / multi-step
```

## 什么时候 Prompting 就够了

绝大多数场景。一个迹象：你能用**清晰的中文 / 英文**描述清楚"我要什么、不要什么"，那 prompt 就有戏。

实测下来，给一个 Claude Opus 4.7 / GPT-4.5 写好的 prompt：

- 分类任务 → 90%+ 准确率
- 摘要 / 改写 → 主观满意度 90%+
- 信息抽取 → 95%+ F1
- 复杂推理 → 配合 thinking 模式，复杂数学 / 逻辑都能搞

只有当 prompt 调到极致还不够时，才考虑下一步。

## 什么时候 RAG 是必须的

当模型必须**基于事实**回答，而这些事实**不在它的训练数据**里：

- 公司内部文档问答
- 实时数据查询（昨天的股价、最新的政策文件）
- 法律 / 医学等高频更新的领域知识
- 个人数据（用户的历史订单、自己的笔记）

RAG 的另一个隐性好处：**可解释性**。模型回答能附上"我是基于这段文档说的"，便于人工审计。

## 什么时候 Fine-tune 才是答案

满足**所有**条件才考虑：

1. **格式 / 风格难以靠 prompt 复现**
   例如：客服回复的特定句式、品牌特定的写作风格、某种独有的输出结构

2. **有 1000-10000 条高质量标注数据**
   太少 fine-tune 学不到东西，太多就该问问是不是任务设计有问题

3. **prompt 已经调到极致**
   不是"我懒得写 prompt 所以 fine-tune"。这是最常见的误用

4. **能接受调试难度高**
   Fine-tune 出来的模型行为相对黑盒，迭代成本高

5. **延迟 / 成本要降**
   fine-tune 小模型替代 prompt 大模型，能省 5-10 倍成本，但前提是任务足够窄

## 一个真实的踩坑

经常见到的反模式：

> "我们的客服回复语气总是太机器化，要 fine-tune 让它更像人。"

实际上：

- 90% 概率 prompt 里没写"用真人客服的口吻"
- 99% 概率没给 3-5 个真人客服的样例 few-shot
- 100% 概率 fine-tune 的标注成本 > 改 prompt 的成本

**先把 prompt 改到极致**。改完还不行再聊 fine-tune。

## 三者组合：现实里的样子

实际生产系统里，**三者经常组合**：

```
用户问题
  ↓
[Prompting] 路由 prompt 判断意图
  ├── 知识问答 → [RAG] 检索 + Prompting 生成
  ├── 简单聊天 → [Prompting] 直接生成
  └── 特定垂类任务 → [Fine-tuned 小模型] 处理
```

不是非此即彼。**用对每件武器**才是关键。

## 决策清单

每次想"是不是要 fine-tune"时，问自己：

- [ ] 我能用一段清晰的话描述任务吗？
- [ ] 我试过 5 种以上 prompt 写法吗？
- [ ] 我加过 few-shot examples 吗？
- [ ] 我用过更强的模型测试过吗？
- [ ] 我用过 thinking / CoT 吗？
- [ ] 我有 1000+ 标注数据吗？

**前 5 个里有 yes 没全的**——回去先把 prompt 调好。
**第 6 个是 no**——根本没法 fine-tune。

90% 的"想 fine-tune"，在前 5 个问题里就该回到 prompt 工作上。

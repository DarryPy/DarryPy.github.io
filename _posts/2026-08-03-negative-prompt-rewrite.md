你写过这样的 prompt 吗:"不要用 markdown"、"不要超过 100 字"、"绝对不要编造数据"。发出去,该犯的错一个没少。你以为是模型笨,其实是你把它的注意力往错的地方引了。否定指令的麻烦不在模型不听话,而在于它得先在脑子里"想象"那个被禁止的东西,才谈得上避开——这一步本身就在给错误答案加权。

## 为什么"不要做 X"经常失灵

语言模型是按概率续写 token 的。当你写"不要提到价格",这句话把"价格"推到了上下文的高激活区。模型读到它,相关联想被点亮,反而更容易顺着写出价格。这和"现在别想一头粉红色的大象"是同一回事:否定词 not 是个很弱的信号,它压不住被它修饰的那个强名词。你越强调什么,它就越容易冒出什么。

还有一层更隐蔽的原因。RLHF 阶段模型学到的是"照着指令的正面语义走",而不是做严格的逻辑取反。它对"做 X"这类祈使句响应最好,对嵌套否定、双重否定则常常读偏。当你把三四个"不要"堆在一句话里,模型要同时维持多个否定状态,注意力预算被耗散,结果就是抓大放小——最刺眼的那条勉强守住,剩下的悄悄破防。

位置也会放大这个问题。禁令如果埋在一长段指令的中间,它离最终生成的距离远,信号衰减更厉害;等模型写到关键处,早把那句"不要"忘在脑后。你把同样的禁令挪到 prompt 末尾、独立成行,遵守率往往肉眼可见地上一个台阶。所以就算暂时还没改成正向,先把否定句从段落里拎出来单独放,也是一次几乎零成本的加固。

## 一个可复现的实验

我拿同一个任务测过两版 prompt。任务是把一段用户评论改写成一句话摘要。A 版写"不要带任何情绪词";B 版写"只用中性、客观的陈述句"。各跑 50 次,A 版有 11 次仍漏出"太差了""很惊喜"这类词,B 版只有 2 次。差别不在模型,在于 B 版给了它一个能对齐的正向目标,A 版只给了一个要躲开的坑。

关键是这种失灵是概率性的,你随手试一次很可能正好没踩雷,于是误以为 prompt 没问题,上线后才在长尾里翻车。所以测否定指令一定要跑批量,别拿单次输出下结论。

```text
# A 版(否定式,易失灵)
把下面的评论改写成一句话摘要。
不要带任何情绪词,不要主观评价。

# B 版(正向式,更稳)
把下面的评论改写成一句话摘要。
只使用中性、客观的陈述句,聚焦事实与数字。
```

## 把否定改写成正向约束

改写的核心是问自己一句:"如果不能做 X,那到底该做什么?"把禁令翻译成一个可执行的目标。"不要太长"→"控制在 3 句以内";"不要用专业术语"→"用初中生能懂的话解释";"不要跑题"→"每段第一句必须回应问题本身"。正向约束给了模型一个能瞄准的靶心,而不是一片要绕开的雷区。模型天生擅长模仿目标,不擅长回避幽灵。

如果某条禁令实在绕不开——比如合规红线必须写"不得输出用户手机号"——那就成对地写:先说禁令,紧跟一个替代动作,"遇到手机号时用星号打码,只保留后四位"。给模型一条出路,它才不会卡在"我该往哪走"的空白里乱填。单独一个"不许",等于把它推到悬崖边却不告诉它桥在哪。

| 否定指令(易失灵) | 正向改写(更稳) |
| --- | --- |
| 不要用 markdown | 输出纯文本,段落之间用空行分隔 |
| 不要超过 100 字 | 用 60-80 字回答 |
| 不要编造不知道的 | 没有依据时回答"资料中未提及" |
| 不要太正式 | 用朋友聊天的口吻 |
| 不要遗漏步骤 | 按 1、2、3 编号列出每一步 |

也别矫枉过正。当禁止的行为没有明确对立面时,否定反而是最简洁的表达。"回答里不要包含任何链接"就比硬凑一个正向说法清楚,因为它排除的是一整类东西,你没法用一个正向目标把它们全罩住。判断标准很简单:这条禁令能不能自然翻译成一个具体动作?能,就翻译;不能,就保留否定,但务必配上具体、可判定的边界,让模型知道界线画在哪。

## 结构化兜底:让格式自己排除坏输出

有些约束光靠改写还不够,你得把它搬进结构里。要求 JSON 输出、给定 enum 字段、限定 schema,坏答案在格式层面就被挡掉了——这比任何"不要"都硬。想让模型别自由发挥,就把它能填的位置提前挖好;想让它别输出多余解释,就规定"只返回代码块,前后无任何文字"。当合法答案的形状被钉死,非法答案连出生的机会都没有。

再往上一层,是把约束交给采样和解码去执行,而不是全靠自然语言祈求。用 constrained decoding 强制符合 schema,用 stop token 截断跑题,用 max_tokens 兜住长度。自然语言里的"不要"是软约束,模型可以违背;而这些机制是硬约束,它想违背都没有通道。能用结构解决的,就别在 prompt 里反复念咒。

## 踩坑清单

- 一条指令里塞五个"不要",不如一句清晰的正向目标。
- 实在要禁,就"禁令 + 替代方案"成对写:不做 X,而是做 Y。
- 别把 not 藏在长句中间,模型容易读丢;短句、独立成行更稳。
- 关键约束用结构(JSON / enum / schema)或解码机制锁死,别只靠自然语言。
- 改完 prompt 一定跑批量对比,别凭一次输出下结论——否定指令的失灵是概率性的。

一句话:模型不会"避开"什么,它只会"奔向"什么。你要做的,是把靶心画对。

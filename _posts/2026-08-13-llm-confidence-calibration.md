你上线一个客服 bot,它斩钉截铁地答错了退款政策,语气跟答对时一模一样。问题不在它答错——模型总会错——而在它错得毫无预警,没有任何信号让你在放行前拦下来。置信度校准 (calibration) 要解决的正是这件事:让模型说"90% 确定"时,真的有约 90% 的概率是对的。

这不是学术洁癖,而是决定你敢不敢在关键链路上做自动放行的前提。一个校准良好的置信度,等于给下游多了一个可信的开关:该转人工的转人工,该二次检索的去检索。少了它,你的所有阈值都是拍脑袋定的,拦不住真正该拦的那批。

## 什么叫"校准好"

一个模型输出的置信度 p,如果它所有说"70% 确定"的样本里,真实正确率也接近 70%,就叫校准良好。校准和准确率是两回事:一个准确率只有 60% 的模型可以完美校准(它从不虚张声势),一个准确率 95% 的模型也可能严重过度自信,张口就是 99%。

生产里你要的是两者兼顾,但校准这一半账几乎总被忽略。大家盯着 leaderboard 上的准确率,没人问模型报出来的置信度值不值钱。结果就是准确率漂亮、可置信度全是水分,下游拿着一堆虚高的 0.95,根本没法据此做决策。

衡量指标是 ECE (Expected Calibration Error):把预测按置信度分成若干桶,算每个桶里"平均置信度"和"实际正确率"的差,再按样本数加权平均。ECE 越低越好,0.02 以下算相当健康,超过 0.1 就说明置信度基本不能用。

配套的可视化叫 reliability diagram:横轴是置信度桶,纵轴是该桶实际正确率,对角线代表完美校准。曲线压在对角线下方就是过度自信——这几乎是所有经过 RLHF 的模型的通病,它们被人类偏好训得爱把话说满,语气一律坚定。

举个具体的:你收集 1000 条问答,把模型报 0.9 置信度的那批挑出来共 300 条,发现实际只答对了 240 条,正确率 0.8。这 0.1 的差就是这个桶的贡献,乘以它的样本占比再累加到别的桶,就是 ECE。看数字比看感觉靠谱,一张 reliability diagram 能立刻暴露模型是全程虚高,还是只在某个区间失真。

## 三种拿到置信度的方式

LLM 不像传统分类器天然吐概率,你得想办法把它挖出来,每种方式都有取舍:

| 方式 | 怎么拿 | 优点 | 坑 |
|------|--------|------|-----|
| Logprob | 取答案 token 的对数概率 | 便宜、连续、可微 | 长答案要聚合;闭源 API 未必给 |
| Verbalized | 让模型直接输出"确定度 0-100" | 无需 logprob,闭源也能用 | 爱扎堆 90/95,几乎必须重校准 |
| 采样一致性 | 同问题采样 N 次看答案分歧 | 抓幻觉很灵 | 成本 ×N,慢 |

Logprob 看着最"科学",但长答案要把一串 token 概率聚合成一个数,取平均还是取最小值差别很大,而且 RLHF 后的分布本来就偏。Verbalized 最省事,闭源模型也能用,代价是模型报的数字扎堆在 90 和 95,几乎没有区分度,必须再校准一层才能用。

聚合 logprob 也有讲究:一句答案里有的 token 是虚词、概率天然高,有的才是关键实体。直接取整句均值会被大量高概率虚词稀释,让置信度偏高。更稳的做法是只看关键 span 的最低 token 概率,或对结构化输出只算字段值那几个 token——弱在哪儿,置信度就该被谁拉低。

实战里 verbalized 加采样一致性组合最稳:让模型先自评一个数,再用多次采样的答案分歧度做交叉验证,分歧大就把置信度往下压。单靠模型自报的数字,基本等于让考生自己给自己打分,松紧全凭它心情。

## 后处理校准:温度缩放

原始置信度往往不能直接用,得再校准一层。最简单有效的是 temperature scaling:在一份独立验证集上学一个标量 T,把 logits 除以 T 之后再做 softmax。它只调整概率分布的锐度、不改变排序,所以准确率一分不损,只把过度自信压回来。

```python
import numpy as np
from scipy.optimize import minimize_scalar
from scipy.special import softmax

def ece(confs, correct, n_bins=10):
    bins = np.linspace(0, 1, n_bins + 1)
    e = 0.0
    for lo, hi in zip(bins[:-1], bins[1:]):
        m = (confs > lo) & (confs <= hi)
        if m.sum() == 0:
            continue
        e += abs(confs[m].mean() - correct[m].mean()) * m.sum()
    return e / len(confs)

def fit_temperature(logits, labels):
    def loss(T):
        p = softmax(logits / T, axis=1)
        conf, pred = p.max(axis=1), p.argmax(axis=1)
        return ece(conf, (pred == labels).astype(float))
    return minimize_scalar(loss, bounds=(0.5, 5), method='bounded').x
```

拟合出的 T 通常大于 1,正说明原模型过度自信;除以它就把置信度整体往下拉,ECE 往往应声下降一半以上。全程不动模型权重,一份几百条的验证集就够,这也是它比重训模型划算得多的原因。

要注意温度缩放是"全局"的一刀切:它假设过度自信的程度在所有区间一致。如果你的模型在简单题上校准得好、难题上却离谱,单个 T 压不平,这时就得上分段的 histogram binning 或 isotonic regression,按区间分别校准。

## 校准之后:弃权机制

校准的终点不是一张好看的曲线,而是让系统学会说"我不知道"。有了可信的置信度,你才能设阈值:低于 τ 就转人工、触发一次检索、或者干脆回答"信息不足"。校准是因,弃权是果,顺序不能反。

弃权清单:

- 分档处理:大于 0.85 直接答,0.6 到 0.85 附免责声明,低于 0.6 弃权
- 阈值别硬编码:在标注集上,按你能接受的错误率反推出 τ,而不是取整数
- 高风险域(医疗、金融、法律)阈值单独抬高,宁可多弃权也别赌
- 弃权率本身要进监控盘:它突然飙高,往往是数据分布漂移的最早信号

阈值怎么定不该靠直觉。把标注集按校准后的置信度排序,画一条"弃权率-错误率"曲线:你能接受剩下的答案错误率不超过 3%,就沿曲线找到对应的 τ,读出此时要弃权多少比例。这样阈值是从业务容忍度反推的,不是从整数里挑的,换个场景改容忍度重算即可。

弃权不是认怂,而是把不确定性显式地交回给人或流程。一个会在 0.5 置信度时老实转人工的系统,远比一个全程 0.95 却时不时翻车的系统更值得托付关键业务。

校准也不是一锤子买卖,得进你的线上监控。定期拿一小批带标注的线上样本重算 ECE 和弃权率,和上线时的基线比。一旦 ECE 悄悄爬升,通常意味着输入分布已经漂移、校准参数开始失效,这比等到用户投诉才发现要早得多,也是把评估和安全接到一起的关键一环。

## 踩坑清单

- 只盯准确率不看校准:上线后"自信地错"是投诉的重灾区
- 拿训练集算 ECE:必须用独立验证集,否则乐观到失真
- 分桶太细:样本少时每桶噪声大,10 桶是稳妥的起点
- 把 verbalized 的 95% 当真:模型报的数普遍虚高,务必重校准
- 校准一次就不管:换模型版本、改 prompt,老参数全部作废,要重跑

一句话:准确率决定模型答得对不对,校准决定你敢不敢信它说的那句"对"。

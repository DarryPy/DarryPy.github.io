你把模型堆到四十层，loss 曲线在头几百步就开始剧烈抖动，甚至直接 NaN。先别急着把学习率砍半，也别怀疑数据脏了。这类症状里有相当大一部分不是优化器的锅，而是归一化层的位置和形态选错了。归一化是训练里最不起眼、却最容易在深层放大误差的一环，值得你花半小时认真算一笔账。它只占几行代码，影响的却是整条梯度通路能不能走通。

## Pre-Norm 与 Post-Norm 的分水岭

原始 Transformer 用的是 Post-Norm，结构是 `x + Sublayer(x)` 之后再套一层 norm。这个设计在六层、十二层的浅网络上没问题，但一旦堆深，残差主干上会不断累积未经约束的激活值，梯度回传时逐层放大，深层模型几乎必须靠漫长的 warmup 才能勉强稳住。这也是为什么早期 BERT 训练对学习率如此敏感。

Pre-Norm 把 norm 挪进残差分支内部，变成 `x + Sublayer(Norm(x))`。关键差别在于：残差主干上永远是一条没被 norm 干扰的恒等通路，梯度可以近乎无损地直达底层。GPT 系列、LLaMA 全线倒向 Pre-Norm，正是因为它让几十上百层的训练不再需要精细 warmup，学习率的容忍区间也宽了一大截。

从数值上讲，Post-Norm 的问题在于每层的方差会沿深度累加，第 N 层的输出方差近似正比于 N，梯度回传时这个放大因子被逐层连乘，浅层几乎收不到有效信号。warmup 之所以有用，本质是用一段低学习率的缓冲期，让 norm 的统计量先稳定下来。Pre-Norm 把方差增长压成了对数级，这才是它敢用大学习率的底气。

但 Pre-Norm 不是免费的。它的代价是深层的等效更新量会被残差主干稀释，越深的层贡献越小，表现出一种"表征坍塌"的倾向——最后几层学到的东西越来越少。所以你会看到 sandwich norm（在分支前后各加一层）、DeepNorm（给残差分支乘一个与深度相关的缩放系数）这些折中方案，试图把 Post-Norm 的表达力和 Pre-Norm 的稳定性同时拿到手。

DeepNorm 的做法值得单独提一句：它在残差相加时给分支乘上一个约等于层数平方根的系数，同时把初始化按同样的尺度缩小，等于人为压住了深层的爆炸倾向。靠这一招，微软把 Transformer 稳稳堆到了一千层。你不一定用得上千层网络，但这个思路提醒你——归一化和初始化必须一起调，单独动一个往往适得其反。

## RMSNorm 凭什么取代 LayerNorm

LayerNorm 做两件事：先把激活减去均值、除以标准差完成标准化，再用可学习的 `scale` 和 `shift`（gamma 与 beta）恢复表达力。RMSNorm 的赌注是——减均值这一步其实可有可无。它直接砍掉了中心化和 bias，只保留除以均方根再乘 scale，公式简化成 `x / rms(x) * g`，参数量和计算量都少了一块。

这个简化在实践中几乎不掉点，却带来实打实的速度收益。少了一次求均值、少了一组 bias 参数，在动辄几十层、每层多次调用 norm 的大模型里，累积下来的 kernel 启动和访存开销相当可观。LLaMA、Mistral、Qwen 清一色用 RMSNorm，不是跟风，是因为在同等 loss 下它更省时间——训练侧和推理侧都省。

要注意的是，RMSNorm 少了中心化，对输入分布的偏移更敏感一点。如果你在一个原本用 LayerNorm 的架构上直接换成 RMSNorm，最好重新扫一遍学习率，别指望超参能无缝迁移。多数情况下差异很小，但在混合精度或极深网络里，这点敏感度偶尔会成为 loss spike 的诱因。

有一个常被问的问题：既然减均值这步几乎不影响效果，为什么 LayerNorm 当年要做它？答案是历史包袱。LayerNorm 从 BatchNorm 演化而来，中心化在卷积网络里确实重要，搬到 Transformer 后大家默认沿用，直到有人做消融才发现这步在这个场景里近乎冗余。这也是个好教训：别把上一代架构的默认设置当真理，敢做减法往往能捡到白送的加速。

## 藏在归一化里的工程细节

真正坑人的往往不是选哪种 norm，而是精度。归一化内部要做平方、求和、开方，这些操作在 fp16 或 bf16 下极易累积误差甚至溢出。铁律是：无论外面用什么精度训练，norm 的统计量计算都要临时上转到 fp32，算完再转回来。很多"莫名其妙的 NaN"就是有人图省事把这步留在半精度里。

`eps` 的加法位置也有讲究，它必须加在开方之前的分母里防止除零，而不是随手加在结果上。下面是一个标准 RMSNorm 的实现，注意精度提升和 eps 的位置：

```python
import torch
import torch.nn as nn

class RMSNorm(nn.Module):
    def __init__(self, dim, eps=1e-6):
        super().__init__()
        self.eps = eps
        self.weight = nn.Parameter(torch.ones(dim))

    def forward(self, x):
        dtype = x.dtype
        x = x.float()                                  # 统计量必须在 fp32 里算
        rms = torch.rsqrt(x.pow(2).mean(-1, keepdim=True) + self.eps)
        return (x * rms).to(dtype) * self.weight       # 归一化后再转回原精度
```

还有个容易忽视的点：`weight` 的初始化。RMSNorm 的 scale 初始化为全 1 是标准做法，但如果你在做 continued pretraining 或模型合并，norm 的权重同样会被更新，粗暴地重置它们会破坏原模型的校准。归一化层参数量小，存在感低，恰恰因此最容易在迁移时被无意间搞坏。

在分布式训练里，norm 还有个隐藏坑。它要沿 hidden 维求统计量，可这个维度往往正是张量并行切分的方向，于是每张卡只握着一部分激活，必须先做一次 all-reduce 才能算出正确的均方根。框架大多帮你处理好了，但你手写融合算子或改并行策略时，这一步一旦漏掉，单卡看似正常、多卡 loss 却对不上，排查起来极其折磨。归一化的每个细节都在提醒你：越简单的层，越经不起想当然。

## QK-Norm 与归一化的新战场

近两年归一化的战场从残差分支蔓延到了注意力内部。QK-Norm 在计算注意力分数前，先对 query 和 key 各做一次归一化，直接压制点积的数值爆炸。这招在训练超长上下文或超大模型时特别管用——它从源头上抑制了 attention logits 的极端值，让 loss spike 出现的概率显著下降，很多前沿模型已经把它当标配。

别忘了还有一个最容易被无视的归一化：整个网络最后、送进 lm_head 之前的那一层 final norm。它直接决定 logits 的尺度，进而影响 softmax 的温度和训练初期的 loss 数值。有人做权重初始化或模型剪枝时顺手动了它，结果开局 loss 高得离谱还找不到原因。记住主干上每一个 norm 都在参与校准，没有哪个是纯装饰。

把这些放在一起，你会发现归一化早已不是"标准化一下"这么简单的配角。它同时决定了梯度能否顺畅回传、深层是否有效学习、半精度下是否溢出、长上下文是否稳定。下面这张表把主流选择的取舍摊开：

| 方案 | 位置 | 稳定性 | 速度 | 典型使用 |
| --- | --- | --- | --- | --- |
| Post-Norm | 残差外 | 深层差，需 warmup | 中 | 早期 BERT |
| Pre-Norm | 残差内分支 | 好，学习率宽容 | 中 | GPT / LLaMA |
| RMSNorm | 替换 LayerNorm | 好 | 快 | LLaMA / Qwen |
| DeepNorm | 残差缩放 | 极深网络佳 | 中 | 千层级模型 |
| QK-Norm | 注意力内部 | 抑制 logit 爆炸 | 略慢 | 长上下文前沿模型 |

落地时记住这几条踩坑清单：深层训练默认 Pre-Norm，别用 Post-Norm 硬扛；norm 统计量一律 fp32，这是 NaN 的头号防线；`eps` 加在开方前的分母里，不是加在结果上；从 LayerNorm 换 RMSNorm 要重扫学习率；做迁移或合并时别无脑重置 norm 权重；长上下文或大模型频繁 loss spike，先试 QK-Norm 再谈调参。归一化省不了几行代码，却能替你省掉几个凌晨三点看着曲线炸掉的夜晚。

你花三天微调一个模型,domain 任务准确率从 60% 飙到 92%,正准备上线庆祝,测试同事却丢来一句:"它现在连普通多轮对话都接不住了。"这就是 catastrophic forgetting——模型学会新任务,却把原本的通用能力忘得干干净净。它不是玄学,而是梯度下降的必然副作用。今天把它彻底拆开:为什么会忘、怎么量化、有哪些救法、起点如何影响它,以及那个几乎所有人都会做错的数据配比。

## 遗忘是怎么发生的

微调本质是拿新数据的 loss 推动权重移动。你的 domain 数据分布越窄、离预训练分布越远,梯度就越会把模型往一个狭窄区域拽。base model 里支撑通用能力的那些权重方向,在新 loss 面前没有任何约束,于是被无差别覆盖。学习率越高、步数越多、数据越单一,覆盖就越彻底。你看到的"变笨",本质是权重被过度专用化了。

这里有个反直觉的点:数据越少,遗忘反而可能越重。小数据集撑不起足够多样的梯度信号,模型很快把有限样本背下来,进入过拟合区间,权重被少数几个模式牢牢占据。此时它既没学到可泛化的 domain 能力,又丢了通用能力,是最差的一种结局。所以样本量小的时候,更要主动克制训练强度,而不是拼命多训几个 epoch。

更麻烦的是,遗忘往往是隐性的。domain 指标一路上涨会给你一种"训得很好"的错觉,而通用能力的滑坡根本不会出现在训练曲线里。等到线上用户开始抱怨模型答非所问、拒答失灵、多轮记不住,你才意识到代价早在第几百步就已经付出了。所以第一步永远不是调参,而是想办法把退化变得可见。

## 先把退化变成一个可以看见的数字

正确做法是在微调前固定一组 regression 评测集:通用问答、多轮对话、指令遵循、安全拒答各留几十到上百条,微调后逐个跑分,和 base model 横向对比。你要找的不是 domain 分数最高的 checkpoint,而是 domain 提升可观、通用回撤在可接受范围内的那个。没有这把尺子,后面所有技巧都是盲人摸象。

评测集不必很大,关键是覆盖你真正在意的能力维度。最省事的办法是从公开评测里各抽一小撮:通用知识、数学、代码、指令遵循、安全,再补几十条贴近业务的真实 query,用一个更强的模型或人工给出参考答案。这份基线一旦建好,后面每次微调都能复用,边际成本几乎为零,却能救你很多次上线事故。

评测还要贯穿整个训练过程,而不是只在最后跑一次。每隔若干步存一个 checkpoint 并回测,你会看到一条清晰的权衡曲线:domain 一路上升,通用先平后跌。两条线的交叉区间,就是你该停下的地方。early stopping 之所以对遗忘有效,道理正在于此——它帮你踩在退化真正加速之前那一步。

## 四类救法与取舍

对付遗忘的手段就那么几类,核心都是"少动 base 的权重"。放一张对比表:

| 方法 | 原理 | 遗忘抑制 | 主要代价 |
|---|---|---|---|
| 小学习率 + 早停 | 少移动权重 | 中 | domain 上限被压低 |
| LoRA / 冻结主干 | 只训低秩增量 | 强 | 复杂任务容量不足 |
| Replay 混数据 | 掺入通用样本 | 强 | 需准备高质量回放集 |
| L2-SP / EWC 正则 | 惩罚偏离 base | 中 | 调 λ 麻烦,收益有限 |

实战里最稳的组合是 LoRA + Replay:LoRA 从结构上锁住绝大部分权重,Replay 再从数据分布上补齐,两者叠加通常比单用任何一种都稳。正则类方法听起来优雅,但 EWC 要估 Fisher 矩阵、L2-SP 要调惩罚系数,工程成本高而收益经常不如直接混数据,除非有明确理由,否则不必先上。

LoRA 抗遗忘也有讲究:秩越大、注入的层越多,容量越强但越接近全参微调,抗遗忘的优势随之减弱。稳妥的起点是中等秩、只挂在 attention 的投影层上,先看 domain 能不能吃下去,不够再逐步往上加。把 LoRA 当成一根可以调松紧的带子,而不是一键见效的银弹,你才算真正会用它。真正决定成败的从来不是选了哪个方法,而是有没有边训边回测。

手段之外,起点也是一种选择。从哪个 checkpoint 起步,同样直接影响遗忘的严重程度。从 base(未对齐)模型微调,你不用担心破坏对齐能力,但要自己补齐指令遵循;从 instruct(已对齐)模型微调,起点能力强,可你的每一步梯度都在啃食那些来之不易的对齐权重,遗忘风险天然更高。这不是谁更好的问题,而是你在为不同的代价买单。

一个实用的判断标准是任务复杂度与数据量。domain 任务简单、数据不多时,优先在 instruct 上小步微调,能借到现成的对齐能力;任务复杂、数据充足时,从 base 起步反而更可控,因为你有足够信号重新长出通用能力,而不必在别人对齐好的权重上小心翼翼。起点选错,后面再多技巧都是在还债。

## 数据配比:最有效也最容易做错

Replay 的关键是比例,不是有没有。业界经验是通用样本占 5%–30%,domain 越窄、base 能力越重要,就往高了配。别用原始预训练语料回放,那太糙;用一批高质量的通用 SFT 数据,效果和稳定性都更好。下面是最小可用的混合逻辑:

```python
# domain : general = 8 : 2 的混合采样
import random

def mix(domain_data, general_data, ratio=0.2):
    n_gen = int(len(domain_data) * ratio / (1 - ratio))
    pool = domain_data + random.sample(
        general_data, min(n_gen, len(general_data)))
    random.shuffle(pool)
    return pool

train_set = mix(domain_data, general_sft, ratio=0.2)
```

最容易踩的坑是顺序:一定要在整个训练集层面把两类数据打散,而不是先训 domain 再补 general。后者等于又做了一次顺序微调,通用样本刚拉回来的能力,会在后续 domain 步里被再次冲掉,遗忘照样发生。配比对了、打散了,你才真正吃到 Replay 的红利,否则只是自我安慰。

万一没防住、模型已经忘了,还能救回来吗?能,但代价不小。最直接的办法是拿一批通用数据在退化后的模型上继续训几步,把分布拉回来,相当于一次反向 Replay;缺点是可能又反过来伤到刚学好的 domain,需要重新回测权衡。这本质上还是在原来的问题里打转,只是换了个方向,并没有真正跳出遗忘的循环。

更取巧的做法是 model merging:把微调后的权重和原始 base 按比例线性插值,domain 能力保留大部分,通用能力找回一截,一个 0.7/0.3 的加权常常就能显著回血,还不用重新训练。但请记住,这些都是事后补救,远不如一开始就配好 Replay、选对起点、盯住回测来得干净利落。

## 踩坑清单

- 只看 domain 指标、不回测通用能力,上线才发现退化
- 学习率照搬预训练配置,base 权重被直接冲垮
- 用 full fine-tune 硬刚小数据集,过拟合叠加遗忘
- Replay 数据质量差,通用没救回来还把 domain 带偏
- 分阶段"先专才后通用",顺序训练重新引发遗忘
- 不存 base 评测基线,能力回撤了都无从对比

一句话:遗忘不是要不要防的问题,而是你有没有那把回测的尺子。先能测出退化,LoRA、Replay、正则、merging 才谈得上取舍;连测都测不出来,再多技巧都只是碰运气。记住这个次序——先造尺子,再动手训,最后才轮到挑方法。

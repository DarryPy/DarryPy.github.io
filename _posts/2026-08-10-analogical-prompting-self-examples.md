你写过 few-shot prompt 就懂那种拧巴：为了让模型解一类题，你得手动翻出三五个示例，还要挑难度相近、格式统一、覆盖边界的。示例选窄了模型泛化不动，选宽了又稀释重点。更糟的是，换个题型这批示例就作废，你得从头再来一遍。Analogical Prompting 的思路很直接——既然模型自己见过海量例题，为什么不让它先造几道相关的，再动手解你真正的题？

## few-shot 的隐性成本，比你想的高

第一是维护成本。每个任务一套示例，任务一多就变成了示例仓库，还得随模型升级重新校准一遍。第二是选择偏差，你挑的例子往往偏向自己熟悉的解法，模型被带着走，遇到冷门变体就翻车。第三是上下文占用，三五个长示例动辄上千 token，在长文档任务里这是实打实的钱。这三块叠起来，你会发现真正花在"把示例伺候好"上的精力，常常比调 prompt 正文还多。Analogical Prompting 想一次性绕开这三点，代价只是一段固定指令。

## 核心机制：先自造例题，再解目标题

方法出自 Google 2023 年的论文，一句话概括：在正式作答前，让模型先"回忆"并生成几道与当前问题相关的例题，连解法一起写出来，再据此解你真正要问的题。它把 few-shot 里"人来提供示例"这一步，换成了"模型自己从记忆里检索并生成示例"。你付出的只是一段可复用的指令，示例由模型按题目临场定制，题变了它就换一批，不用你再动手。

背后的直觉是，大模型在预训练里见过天量题目，相关的解题范式其实早就压进了参数，缺的只是一个把它唤醒的触发动作。让模型自己举例，正是最省事的触发方式——它一边造题一边就把对应的推理套路提到了工作记忆前排，接着解正题时自然顺手。这也解释了为什么它对"有套路可循"的题特别灵，对没套路的常识题几乎无效。

一段能直接抄的 prompt 模板：

```text
# 目标问题
{your_question}

# 请按以下步骤作答
1. 回忆 3 道与上面问题相关、但不完全相同的例题
2. 逐题写出解法与最终答案
3. 归纳这些例题共用的方法
4. 用该方法解目标问题，给出最终答案
```

关键全在第 1 步那句"相关但不相同"：太相似会退化成抄答案，太发散又借不上力。你可以把数量从 3 调到 5，复杂题多给几道，简单题给 1 道甚至直接跳过这一步。

举个例子就清楚了。拿"一个长方形周长 24，长是宽的 2 倍，求面积"来说，模型会先自造三道：正方形周长求边长、已知长宽求面积、二元一次方程组求解。它在解这三道热身题时，顺手把"周长公式→设未知数建立方程→回代求面积"这条链路激活了，等回到目标题几乎不会漏掉"先设未知数"这一步。对比直接甩一句题干，自造例题相当于让模型正式答题前先热了个身，推理链更完整，出错点也更少。

## 两个进阶变体，按题型挑

原始方法自造的是"例题"，但同一套思路还能变形。第一种是自造知识而非例题：碰到知识密集型问题——某个 API 的用法、某条物理定律、某种设计模式——先让模型写出相关的定义、公式和注意事项，再据此作答，相当于给自己临时搭了个知识底座，比空手硬答稳得多。第二种是例题加知识混合：先归纳方法论、再配一道范例，推理链里既有抽象规则又有具体锚点，复杂题上通常比单用例题更扎实。选哪种取决于你的题吃"套路"还是吃"事实"：纯推理题偏前者，需要背景知识的问答偏后者，拿不准就两样都给一点，让模型自己取用。

## 什么时候用，什么时候别急着上

它不是万金油。下面这张表帮你快速判断该不该用：

| 场景 | 建议 | 原因 |
|------|------|------|
| 数学/逻辑/代码推理 | 优先用 | 有可迁移的解题范式，收益最大 |
| 常识问答、闲聊 | 别用 | 没有范式可归纳，纯浪费 token |
| 强格式抽取(JSON) | 慎用 | 自造例题可能带偏最终输出结构 |
| 小模型(7B 以下) | 慎用 | 自造例题质量差，反而误导 |
| 手头有现成好示例 | 用 few-shot | 人工示例更可控 |

一个反直觉的点：模型越强，Analogical Prompting 越划算，因为它自造的例题质量高、范式准；模型越弱，越该老老实实喂人工示例，别指望它自己举出靠谱的例子。

## 落地清单与一句忠告

真上手前照着走一遍：

- 先在 5-10 道代表性题上做 A/B，对比直接问、few-shot、analogical 三种的正确率，别凭感觉
- 例题数量从 3 起步，按题目复杂度增减，别无脑堆到 10 道
- 指令里明确写"相关但不同题"，否则模型爱造几乎一模一样的题来蒙混
- 把自造例题和最终答案分成不同输出段，方便你只取答案、丢弃中间过程
- 对延迟敏感的场景先算笔账：它比直接问多烧一截 token 和响应时间

一句话收尾：few-shot 是你替模型准备好参考答案，Analogical Prompting 是让模型自己开卷。前者可控，后者省心——当任务有章可循、模型又足够强时，把"选例题"这件苦差事还给模型，往往比你手挑更聪明；反过来，题没套路或模型不够硬，就老实回去写人工示例，别为了省事赔上正确率。

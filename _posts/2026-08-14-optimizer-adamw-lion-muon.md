你训到一半发现显存卡在优化器状态上，第一反应可能是换更小的 batch，但真正的杠杆往往在优化器本身。AdamW 每个参数要存两份动量，7B 模型光优化器状态就吃掉 50GB 以上显存。换一个优化器，有时比换卡更划算。这篇把 AdamW、Lion、Muon 三个当下最值得考虑的选项摊开讲，再补上怎么做一次可信的对比实验，帮你在开训前把这个决定做对。

## AdamW 为什么还是默认

AdamW 到今天仍是绝大多数 LLM 预训练的第一选择，原因不是它最强，而是它最稳。一阶动量加二阶动量的自适应学习率，让它对超参不敏感，几乎不用调就能跑起来。代价是每个参数额外存两个 FP32 状态，显存开销是参数量的两倍。你如果没有明确理由，预训练和 SFT 默认它不会错。

真正需要留意的是它的 betas 和 weight decay。大模型训练里 beta2 常从默认 0.999 调到 0.95，让二阶动量对梯度突变更敏感，能明显缓解 loss spike。weight decay 建议解耦成独立超参，不要跟学习率耦合，0.1 是常见起点。这两个小调整，往往比换优化器本身收益还稳还快。

如果你只是嫌它吃显存，先别急着换算法。8-bit Adam 把优化器状态量化到 int8，几乎无损地砍掉一半开销；再配合把状态 offload 到 CPU 或 NVMe，单卡也能撑起更大的模型。很多时候「显存不够」并不是换 Lion 的理由，而是你还没把 AdamW 的省显存手段用满。

## Lion — 符号更新省一半显存

Lion 是 Google 用符号搜索搜出来的优化器，核心只做一件事：用动量的符号决定更新方向。它只需维护一份动量状态，显存比 AdamW 直接省一半，这在显存吃紧时非常诱人。更新只取正负号，看似粗暴，数值稳定性反而不差，大规模预训练里已有不少成功案例。

但 Lion 的学习率要比 AdamW 小 3 到 10 倍，weight decay 要相应放大，这是最容易踩的坑，照搬旧值几乎必崩。它对 batch size 也敏感，小 batch 下噪声被符号放大，表现常不如 AdamW。经验是：大 batch 预训练可以认真试 Lion，小规模微调还是老实用 AdamW 更省心。

还有一个容易被忽略的点：符号更新让每一步的步长几乎固定，学习率调度对它的影响比 AdamW 更直接。你调 warmup 和 cosine 衰减时要更保守，衰减尾部别压得太狠，否则后期几乎不再更新。把这几个细节对齐了，Lion 才能真正把省下的显存换成有效训练。

## Muon — 2026 年最值得试的新变量

Muon 是近两年冒出来、被越来越多前沿团队采用的优化器，思路是对二维权重矩阵的更新做正交化（近似 Newton-Schulz 迭代），让每一步更新的方向分布更均匀，避免少数几个方向主导梯度。实测在相同算力预算下收敛更快，是少数敢正面挑战 AdamW 统治地位的方案。

它的关键限制是只处理矩阵参数，embedding、LayerNorm、bias 这些仍要交给 AdamW，所以实际是个混合优化器。工程上要按参数形状分组，别把一维参数塞给 Muon，否则直接报错或发散。学习率也得重新扫，不能照搬 AdamW 的数值，通常要大上一截。

正交化那步 Newton-Schulz 迭代本身有额外算力开销，但因为只做几次矩阵乘、且能用 bf16 跑，摊到整体训练里几乎可以忽略。真正的成本在调参和工程接入：你得改优化器分组、重扫 lr、验证分布式下的通信没被破坏。愿意付这份工程税，它给的收敛加速通常对得起投入。

```python
muon_params, adamw_params = [], []
for name, p in model.named_parameters():
    if p.ndim == 2 and "embed" not in name and "lm_head" not in name:
        muon_params.append(p)      # 二维权重矩阵走 Muon
    else:
        adamw_params.append(p)     # embedding / norm / bias 走 AdamW

optimizer = [
    Muon(muon_params, lr=0.02, momentum=0.95),
    AdamW(adamw_params, lr=3e-4, betas=(0.9, 0.95), weight_decay=0.1),
]
```

## 三者横向对比与选型

把三者摊到一张表上，差异一目了然。别凭感觉选，先看你的真实瓶颈是显存、算力还是稳定性，再对号入座。

| 维度 | AdamW | Lion | Muon |
| --- | --- | --- | --- |
| 显存状态 | 2×参数 | 1×参数 | 矩阵1× + 其余2× |
| 调参难度 | 低 | 中（lr 要缩小） | 中高（需重扫 lr） |
| 收敛速度 | 基准 | 接近基准 | 通常更快 |
| batch 敏感度 | 低 | 高 | 中 |
| 成熟度 | 最高 | 中 | 上升中 |
| 适用场景 | 通用默认 | 大 batch 省显存 | 追求算力效率 |

选型其实不用纠结：没有强诉求就 AdamW；显存是唯一瓶颈、且是大 batch 场景，先试 8-bit Adam，不够再考虑 Lion；想在固定算力下压缩训练时间、又愿意花时间调参，Muon 值得认真做一轮 A/B。切忌因为「新」就无脑上 Muon，调不好照样烧钱，还多背了工程复杂度。

## 怎么做一次公平的对比

换优化器最怕的是拿到一个不可信的结论，然后基于它做几周的决策。想比得公平，第一条是固定一切非优化器变量：同样的数据顺序、同样的随机种子、同样的 batch 和序列长度，只让优化器和它必须的 lr 变。任何一个别的变量动了，差异就说不清是谁带来的。

第二条是给每个优化器单独扫学习率，而不是共用一组。不同优化器的最优 lr 差一个量级很正常，用 AdamW 的甜点值去评判 Lion，等于让对手先输三招。至少扫三到四个量级点，找到各自的最优，再拿最优对最优比，结论才立得住。

最后别只盯前期 loss。早期下降快的优化器，中后期可能被反超；真正要看的是相同 token 预算下的最终验证 loss，以及下游任务表现。跑一个小规模但足够长的代理实验，比在全量训练上赌一把要省钱得多，也让你敢把结论推广到大模型上。

代理实验的规模也别选得太小。参数量太少时，优化器之间的差距会被噪声淹没，甚至给出反向结论。经验是至少用几亿参数、训到 loss 曲线明显进入平台期，再看排名。规模选对了，你在几百块钱算力上得到的结论，才有底气搬到几十万块钱的正式训练上去。

## 踩坑清单

- 换优化器必重扫学习率，照搬旧值几乎必崩
- Lion 的 lr 要比 AdamW 小一个量级，weight decay 反而要放大
- Muon 只喂二维矩阵，一维参数留给 AdamW，否则报错或发散
- beta2 从 0.999 降到 0.95，能显著减少 loss spike
- 嫌 AdamW 吃显存，先上 8-bit 和 offload，再谈换算法
- 对比优化器要固定随机种子和数据顺序，否则结论不可信
- 别只看前 1000 步的 loss 曲线，早期快不代表最终收敛更好

优化器从来不是银弹，但选错会让你白烧一周算力。开训前花半天把这个决定做对，再花半天设计一次公平的对比实验，永远比训到一半半夜救火划算。

你调一个大模型,大半的 loss 曲线灾难都能追到两件事:学习率的数值,和它随时间怎么变。前者决定你会不会开局就把权重炸飞,后者决定训练后半程模型还学不学得进去。很多人图省事把 learning rate 设成一个常数丢进去跑,然后困惑为什么 loss 到中途就躺平、验证集也不再往下走。这篇把学习率调度和优化器这两根隐形缰绳一次讲清楚,顺带把峰值怎么定、优化器怎么挑也说透。

## 开头为什么必须 warmup

训练最初那几百步,模型权重还是随机初始化的状态,梯度方向极不稳定,方差大得吓人。更麻烦的是 Adam 这类优化器要靠滑动平均去估计梯度的一阶、二阶动量,开局样本太少,分母上那个二阶估计会偏得离谱,算出来的更新步长忽大忽小。这时候直接上满学习率,等于让没热身的人起跑就百米冲刺,极易拉伤——具体表现就是训练几十步后 loss 突然飙成 NaN,再也拉不回来。

Warmup 的做法很简单:让学习率从接近 0 在前若干步线性爬升到峰值,这段通常占总步数的 1% 到 3%。它给了动量估计一个攒样本的窗口期,也让权重在小步长里先挪到一个相对安全的区域。经验规律是模型越大、global batch 越大,warmup 就得越长,几千步的预训练里 warmup 设个两三千步都不稀奇。记住它是保命项,不是可有可无的调参选项。

warmup 的形状也不止线性一种,constant warmup、指数 warmup 都有人用,但绝大多数场景线性就够了,别在这上面过度纠结,把步数占比调对才是重点。另外光靠 warmup 还不足以完全稳住早期,它的黄金搭档是 gradient clipping:把梯度范数裁到某个阈值(常见 1.0),挡住偶发的巨大梯度尖峰,一头一尾守住训练最脆弱的开局阶段。

## Cosine 的统治与它的死穴

过去几年最主流的组合是 warmup 接一段 cosine 衰减:学习率像半个余弦波,从峰值平滑地降到接近零(实践里一般留个 10% 的地板,不真的归零)。它之所以好用,是因为衰减曲线平滑没有突变,而且末段那段极低的学习率天然带精细打磨的效果,能把 loss 再往下压一小截,几乎所有开源预训练模型都这么训。

但 cosine 有个绕不过去的硬伤:你必须在开训之前就把总步数写死,因为余弦曲线的形状完全依赖终点在哪。这意味着一旦你想中途加 20% 的数据继续训,或者想提前叫停拿个 checkpoint 出来用,曲线就全对不上了——要么末段那段关键的低学习率精调根本没走完,模型欠火候;要么你得从头重训,之前烧的卡全白费。做 scaling law 消融、反复调数据配比的团队,最恨的就是这一点。

还有个常见误区顺带说清:cosine 的地板不该真设成 0,一般留峰值的 10% 左右。否则末段学习率无限趋近于零,模型几乎停止更新,那段本来最珍贵的精调步数直接变成空转,白白浪费算力。

## WSD:可以随时叫停的调度

WSD(Warmup-Stable-Decay)就是冲着这个死穴设计的,MiniCPM、DeepSeek 等团队都在用,现在越来越像新的默认选项。它把训练拆成三段:warmup 负责爬升,Stable 段用一个恒定的峰值学习率长跑,最后一小段 Decay 快速把学习率砍到底。妙处在于 Stable 段可以无限延长,你想训多久训多久,不需要提前承诺总量。

真要出模型时,再从任意一个 stable checkpoint 拉出来,单独跑那段短 decay(通常占总量 10%-20%)就行。更实用的一个观察是:decay 段往往会出现一次明显的 loss 二次下降,而且如果你把这段安排在高质量数据上退火,收益还会更大。一个极简 WSD 调度实现长这样:

```python
def wsd_lr(step, warmup, stable_end, total, peak):
    if step < warmup:                      # 线性爬升
        return peak * step / warmup
    if step < stable_end:                  # 恒定长跑
        return peak
    # 末段线性衰减到 0
    return peak * (total - step) / (total - stable_end)
```

这么写的直接好处是,Stable 段沿途产出的每个 checkpoint 都是「半成品但可续」的:同一批权重能反复拿去做 scaling law 实验、数据配比消融,再各自跑短 decay 出结果,省下的算力相当可观。

WSD 还有个隐藏红利:decay 段又短又可复用,让你能用同一条 Stable 主干喂不同的退火数据,分别产出「代码强化版」「中文强化版」等多个变体,而不必各自从头训。做领域模型、多语言分支时,这种一主干多分支的省钱效应尤其夸张。

## 峰值学习率与优化器选型

调度决定曲线形状,峰值决定这条曲线的高度,两者要一起定。峰值太高训练发散,太低则收敛慢还容易卡在差解里。实务上别拍脑袋:小规模跑个 lr range test,让学习率指数上升观察 loss 从下降转向爆炸的拐点,取拐点前一档做峰值;规模放大时,峰值大致随模型变大而调小,batch 翻倍则峰值按平方根或线性同步上调,这是学习率和 batch size 天生成对的缘故。

给个量级参考免得你抓瞎:几亿到十几亿参数的模型,AdamW 峰值常落在 3e-4 到 1e-3 之间,再大就往 1e-4 那一档收。这些只是起点,真正靠谱的值还得靠上面说的 range test 和小规模验证跑出来,别把别人论文里的数字当圣旨照抄。

优化器上也别只会 AdamW。AdamW 稳,但它给每个参数各存一份一阶、二阶动量,显存等于额外吃掉两份权重那么大。下面这张表把常见组合摊开看:

| 调度 + 优化器 | 需预知总步数 | 显存开销 | 适用场景 |
|---|---|---|---|
| Cosine + AdamW | 是 | 高(两份动量) | 一次性定长预训练 |
| WSD + AdamW | 否 | 高 | 需续训 / 多消融实验 |
| WSD + Muon | 否 | 中 | 追求同步数更快收敛 |

Lion 只存一份动量,更省显存,但它对学习率和 weight decay 特别敏感,套用 AdamW 的超参基本必翻车。Muon 是近一两年冒头的新秀,对矩阵参数做正交化更新,报告里同样步数收敛更快,但它只管矩阵层,embedding 和 norm 仍旧交给 AdamW,本质是混搭而非整体替换。换优化器时死记一条:学习率绝不能照搬,Lion 的合适峰值通常只有 AdamW 的三分之一到十分之一。

就算你死守 AdamW,也有几个默认值值得动一动。beta2 默认 0.999 在大模型上有时太贪,调到 0.95 会让二阶动量反应更快、对突发波动更抗打;weight decay 建议只作用在权重矩阵上,别顺手把 bias 和 LayerNorm 的参数也一起衰减,那样往往反而伤性能。如果你要在多个规模间迁移超参,可以了解下 muP(最大更新参数化),它让小模型上调好的学习率能几乎直接迁到大模型,省掉在大规模上反复试错的天价成本。

## 踩坑清单

- Warmup 步数别一律写死 2000,大 batch 要按比例加长,否则照样炸 loss。
- 用 cosine 就把总步数算准,中途改数据量约等于白训末段那截精调。
- WSD 的 decay 段别省,直接拿 stable checkpoint 去评测会明显偏弱。
- 换 Lion / Muon 先缩学习率再跑,直接套 AdamW 的值大概率发散。
- 学习率和 batch size 是一对,batch 翻倍时峰值 lr 按平方根或线性同步上调。
- 别忘了留 min_lr 地板,cosine 真归零会让末段几乎不更新、白白浪费步数。

一句话:学习率不是一个数,是一条你要提前规划好的曲线;选调度的本质,是选你未来还改不改主意的自由度。

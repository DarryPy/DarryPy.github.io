你把数据洗得再干净,只要配比错了,模型照样偏科。同样一批 token,code 占 5% 还是 30%,练出来的模型气质天差地别 —— 一个能陪你聊天但写不对循环,一个代码流畅却把常识答飞。数据配比(data mixing)是训练里最被低估的旋钮:它不改变你有多少数据,只决定每类数据在一次训练里被模型看到几次。今天我把这个旋钮拆开讲透。

## 为什么配比是隐形的能力盘子

你可以把预训练想成一场时间分配游戏:总 token 预算固定,给数学多分一点,就得从网页那里扣。模型的能力上限,在你敲定配比的那一刻就大致划定了。经验上 web 是底盘,code 撑起推理与结构化输出能力,数学和长文本决定天花板。

配比从来不是均分。高质量但稀缺的语料(精标数学、教科书)往往要上采样(upsample)跑几个 epoch,而海量低信息的网页反而要下采样。否则模型会被灌成一个只会复读高频套话的机器,benchmark 分数上不去,你还找不到原因。

这里有个反直觉的点:配比权重不等于原始数据占比。你手里 code 只有全量的 10%,但把它上采样两轮,它在训练里的实际曝光就是 20%。真正影响模型的是"被看到几次",不是硬盘上躺着多少,这一步没算清,后面全是糊涂账。

## 静态配比:经验值起步,别当圣经

最省事的做法是静态配比:开训前定好比例,全程不变。业界公开的配方能给你一个起点,大致长这样:

| 语料类型 | 常见占比 | 作用 | 处理策略 |
|---|---|---|---|
| 网页 web | 40-60% | 语言底盘、常识 | 重度去重、下采样 |
| 代码 code | 15-30% | 推理、结构化输出 | 按 star / 质量筛 |
| 书籍论文 | 5-15% | 长文本、深度知识 | 上采样 1-3 epoch |
| 数学 | 3-10% | 逻辑与推理 | 高质量上采样 |
| 多语言 | 5-15% | 语言覆盖 | 按目标市场调 |

但别把别人的配方当圣经。数据来源不同,同样的比例效果完全不同 —— 你的 code 可能全是低质仓库,别人的是精筛过的。这些数字只是起点,不是答案,拿来直接抄大概率翻车。

更麻烦的是,配比和你的目标强绑定。你要做代码助手,code 拉到 40% 都不夸张;你要做通用对话,拉那么高反而挤掉了常识和语感。先想清楚这个模型将来吃哪碗饭,再回头定比例,顺序反了就是白烧算力。

## 用 scaling law 算,而不是拍脑袋

配比到底怎么定?靠一次次全量训练试错太贵,一轮就是几十万美金。正经做法是用小模型加小数据跑一批 proxy 实验,在几组候选配比上测下游指标,再外推到大模型。近年 RegMix 一类方法更省:直接在几十个迷你模型上拟合"配比到 loss"的回归函数,再预测最优比例。

DoReMi 是这条路的代表:先训一个小的 reference model,再训一个 proxy model,用两者在各 domain 上的 loss 差(超额损失)动态给权重 —— 哪个 domain 学得吃力,就给它更多权重。核心逻辑不复杂:

```python
# DoReMi:按 domain 的超额损失动态分配配比权重
for step in range(T):
    loss = proxy_model.loss_per_domain(batch)      # 各 domain 当前 loss
    excess = loss - ref_model.loss_per_domain(batch)  # 相对参考模型的超额损失
    weights *= exp(eta * excess.clip(min=0))       # 学得吃力的 domain 加权
    weights /= weights.sum()                        # 归一化成配比
# 收敛后的 weights,就是拿去训大模型的静态配比
```

跑出来的权重再当作大模型的静态配比,比纯手调稳得多,也省下反复全量训练的钱。有一点要记牢:proxy 实验一定要看下游 benchmark,而不是只盯着验证集 loss,两者经常打架,loss 低的配比未必能力强。

## 退火阶段:最后 10% 的手感

现在主流的 WSD 式训练把学习率分成 warmup、stable、decay 三段,而 decay(退火)阶段的数据配比是另一个杀手锏。前 90% 用海量普通语料铺底,最后 10% 换成高质量、高相关的语料(精标数学、指令式文本、教科书),同时衰减学习率。

这一手能显著抬高下游指标,几乎不额外花算力。你可以把它理解成:粗放期长身体,退火期练内功。退火阶段高质量语料的占比通常会拉到平时的好几倍,因为学习率在快速下降,这段吃进去的东西留存率最高,值得下重注。

但要小心 —— 退火语料一旦混进脏数据,噪声会被放大成模型改不掉的坏习惯,这段的质量门槛要比铺底期高一个量级。宁可少喂,也别喂脏。退火的配比切换点和衰减节奏也要提前定好,临到最后几步再手忙脚乱地改,大概率会把前面积累的手感一次抖掉。

## 配比不是一次定死:阶段化的思路

把整个训练当成一条固定配方一路灌到底,是老做法。更聪明的团队会做阶段化(phased / curriculum):早期多喂通用网页把语言底子打牢,中后期逐步抬高 code、数学、长文本的比例,让模型在有了语感之后再去啃硬骨头。

这背后的直觉很朴素 —— 人也是先学会说话再学解方程。阶段化的代价是调度更复杂,你得盯着每一段的配比切换点,但换来的是同样算力下更高的推理能力上限,对推理型模型尤其值。

举个具体例子:不少推理型模型会把 code 和数学的占比,从早期的两成分几段抬到后期的近一半,再配合退火补一轮高质量推理数据。你能明显看到中后期 loss 曲线在数学 domain 上重新变陡,那正是模型开始真吃这部分的信号,而不是简单地记住表面模式。

## 微调阶段也逃不开配比

到了 SFT,配比换了个名字叫任务配比。如果你的指令数据里 80% 是闲聊、5% 是代码,模型的编码能力会被闲聊淹没。经验做法是按能力维度分桶(对话、代码、数学、工具调用、安全),给每桶定最低配额,稀缺但重要的能力(如 function calling)要主动上采样。

RLHF / DPO 阶段的偏好数据同理:别让某一类 prompt 占满,否则模型只会在那类问题上讨好你,一换场景就露馅。配比这件事,从预训练一路贯穿到对齐,没有哪个阶段能躲过去。

还有个容易被忽略的坑:SFT 数据要和预训练语料、和评测集都做交叉去重,否则模型在测试题上表现虚高,其实只是把答案背了下来。配比调得再精,一旦发生泄漏,你看到的分数全是幻觉,上线才发现能力对不上。

## 踩坑清单

- 直接抄别人的配方:数据源不同,比例不可移植,只能当起点
- 分不清权重和原始占比:上采样后实际曝光翻倍,不算清全是糊涂账
- 高质量语料上采样过头:同一批数据重复 4+ epoch 就开始过拟合、记忆泄漏
- 忘了去重就调比例:网页不去重,实际配比比你以为的更偏
- 退火语料混进脏数据:最后 10% 的噪声会被放大成坏习惯
- 只看训练 loss 不看下游:配比要用 benchmark 验证,loss 低不等于能力强
- SFT 配比一刀切:不按能力分桶,稀缺技能必被主流任务淹没

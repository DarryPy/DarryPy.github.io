## SFT 解决的是什么问题

预训练模型只会"预测下一个 token"，不会"遵循指令"。
SFT (Supervised Fine-Tuning) 用一份**(指令, 期望回答)** 配对数据，教模型按你想要的方式响应。

90% 的"自定义模型"工作（领域专家、风格定制、特定格式输出）的核心都是 SFT。

## 数据准备：80% 的工作

### 1. 数据格式

主流用 ChatML / OpenAI messages：

```json
{
  "messages": [
    {"role": "system", "content": "你是一个法律助手..."},
    {"role": "user", "content": "合同里这条免责条款合法吗？..."},
    {"role": "assistant", "content": "这条条款根据《合同法》第..."}
  ]
}
```

每行一个完整对话。JSONL 文件存储。

### 2. 数据量

| 任务复杂度 | 推荐数据量 |
|---|---|
| 格式 / 风格调整 | 500-2000 |
| 任务级行为（路由、抽取）| 5000-20000 |
| 领域专长（医学、法律）| 50000+ |

**质量永远 > 数量**。1000 条精选样本胜过 10000 条凑数。

### 3. 数据质量准则

- **多样性**：覆盖所有典型输入分布
- **一致性**：相似问题答案风格统一
- **正确性**：错答案比没答案更糟
- **难度分布**：60% 中等、25% 简单、15% 困难
- **避免数据泄漏**：评估集严格隔离

### 4. 常见数据来源

| 来源 | 质量 | 成本 |
|---|---|---|
| 人工标注 | 最高 | 最贵 |
| 真实业务数据脱敏 | 高 | 中 |
| 大模型生成 + 小模型修正（distillation）| 中-高 | 低 |
| 公开数据集（FLAN / Alpaca）| 中 | 免费 |

最常用组合：**核心 case 人工 + 长尾 case 用大模型 distill**。

## Loss 函数

最常见：**只对 assistant 部分算 loss**，user/system 部分 mask 掉。

```python
labels = input_ids.clone()
labels[~is_assistant_token] = -100  # ignore in CE loss
loss = F.cross_entropy(logits.view(-1, vocab), labels.view(-1), ignore_index=-100)
```

不 mask 的话模型会学着"预测用户问题"，浪费样本效率。

## 训练参数推荐

7B-13B LoRA SFT 起手配置：

```python
from peft import LoraConfig
from transformers import TrainingArguments

lora = LoraConfig(
    r=16,
    lora_alpha=32,
    target_modules=["q_proj","k_proj","v_proj","o_proj","gate_proj","up_proj","down_proj"],
    lora_dropout=0.05,
    bias="none",
    task_type="CAUSAL_LM",
)

args = TrainingArguments(
    output_dir="./out",
    num_train_epochs=3,
    per_device_train_batch_size=4,
    gradient_accumulation_steps=8,   # effective batch = 32
    learning_rate=2e-4,              # LoRA 比全参高一个数量级
    lr_scheduler_type="cosine",
    warmup_ratio=0.05,
    bf16=True,
    save_strategy="epoch",
    eval_strategy="epoch",
    logging_steps=10,
    save_total_limit=2,
)
```

### 关键参数

| 参数 | 推荐 | 调整方向 |
|---|---|---|
| epochs | 2-5 | 多了过拟合；看 eval loss 拐点 |
| effective batch size | 32-128 | 大 batch 稳定但收敛慢 |
| learning rate | 1e-4 ~ 5e-4（LoRA）| 不收敛 → 提高；震荡 → 降低 |
| max_seq_length | 2048-4096 | 看任务，越长越贵 |
| LoRA r | 8-64 | 复杂任务用 32-64 |

## 训练流程

```python
from trl import SFTTrainer

trainer = SFTTrainer(
    model=model,
    tokenizer=tokenizer,
    train_dataset=train_ds,
    eval_dataset=eval_ds,
    args=args,
    peft_config=lora,
    max_seq_length=2048,
    packing=True,  # 多个短样本打包成一个长序列，提高 GPU 利用
)
trainer.train()
trainer.save_model("./final")
```

### 监控指标

- **train loss**：稳步下降，不要平台
- **eval loss**：跟着 train loss 下降，**拐点上扬就过拟合了**
- **token throughput**：GPU 利用率指标
- **gradient norm**：突然飙升说明 lr 太高 / 数据有脏样本

## 部署模式

### 模式 1：保留 LoRA adapter

```python
from peft import PeftModel
base = AutoModelForCausalLM.from_pretrained("meta-llama/Llama-3.1-8B-Instruct")
model = PeftModel.from_pretrained(base, "./final")
```

优点：一个底模配多个 adapter 灵活切换。
缺点：推理时多 5-10% 开销。

### 模式 2：Merge 后导出

```python
merged = model.merge_and_unload()
merged.save_pretrained("./merged-model")
```

优点：可直接用 vLLM / TGI / Ollama 部署，无 adapter 开销。
缺点：每个 adapter 一份完整模型，磁盘贵。

生产单一任务用 merge，多任务复用底模用 adapter。

## 评估必须从训练前就准备

1. **训练集 / 验证集 / 测试集**严格隔离（避免数据泄漏）
2. **训练时 eval loss** 每 epoch 算
3. **训练完成后**用独立测试集跑业务指标（accuracy / F1 / LLM-as-judge）
4. **回归测试**：用 MMLU / GSM8K 测有没有遗忘通用能力

## 常见踩坑

| 坑 | 修法 |
|---|---|
| eval loss 不降 | 数据量太少 / lr 太低 / 数据格式有错 |
| eval loss 先降后升 | 过拟合，降 epoch / 加 dropout |
| 训练 loss 突然 NaN | 学习率太高，或者数据有非法 token |
| 训练慢 | packing=True / batch_size 升 / FlashAttention 开 |
| 部署后效果跟训练时不一样 | 检查推理的 chat template 跟训练时一致 |

## 一份起步 checklist

- [ ] 数据集 ≥ 500 条高质量样本
- [ ] 训练 / 验证 / 测试集 8:1:1 分割
- [ ] chat template 跟底模官方一致
- [ ] LoRA r=16, alpha=32, lr=2e-4 起步
- [ ] 至少跑 3 epoch，看 eval loss 拐点
- [ ] 训练后跑独立测试集 + 通用 benchmark
- [ ] 部署后 A/B 跟基线对比

跑通这套，你就有了**可复制、可迭代的 SFT 流水线**。

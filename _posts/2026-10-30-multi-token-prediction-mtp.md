你训练一个语言模型，默认每个位置只做一件事：预测紧挨着的下一个 token。这就是 next-token prediction，简称 NTP，从 GPT 到今天几乎所有模型都靠它。但 DeepSeek-V3 在这件最基础的事上动了手脚，让每个位置同时预测未来两个甚至更多 token。改动看着不起眼，却一箭双雕：训练阶段信号更密，推理阶段白送一个加速器。这套做法叫 Multi-Token Prediction，简称 MTP，今天把它拆开看清楚。

## 标准 NTP 到底浪费了什么

标准训练里，每个样本在每个位置只算一次交叉熵：给定前文，预测下一个 token，仅此一个监督信号。模型对"再往后一步会发生什么"没有任何直接约束，它学到的是贪婪的、逐字的连贯，而不是对未来的规划能力。

这种短视的代价，在需要提前布局的任务上格外明显。写代码得先想好函数签名再填实现，解数学题要先看到几步之后的目标。只盯着下一个 token 的模型，容易陷入局部通顺、全局跑偏。MTP 的出发点很朴素：前向传播已经把整条序列的表示都算出来了，为什么不顺手多预测几步，把这些本该免费的梯度信号利用起来。

还有个更隐蔽的问题叫 exposure bias。训练时每一步的输入都是真实 token，推理时却得靠自己生成的 token 续写，一旦某步偏了，误差会沿着序列滚雪球。只预测一步的目标无法惩罚这种长程漂移，模型对自己几步之后会把自己带到哪里缺乏感知。MTP 多看几步，相当于逼模型把"我这一步会如何影响后面"也纳入考量，隐状态因此被训得更有全局观。

## MTP 的两种主流接法

第一种是 Meta 2024 论文的并行多头：主干网络不动，在末端并排挂上 n 个独立的输出头，第 k 个头负责预测第 t+k 个 token，训练时把 n 个交叉熵加权求和。实现简单，但几个头之间是平行的，彼此并不知道对方预测了什么。

第二种是 DeepSeek-V3 采用的串行 MTP 模块：每个预测深度配一个轻量 Transformer block，把上一深度的隐状态和"下一个真实 token 的 embedding"拼接后再往下预测。这样预测之间保留了因果链，后一步建立在前一步之上，更贴近自回归的本质，显存占用也比堆一排大输出头更可控。

成本上，串行接法每多一个深度只增加一个 block 的前向，远比并行多头动辄复制整张 unembedding 矩阵（词表动辄十万级）划算。这也是 DeepSeek 在超大词表、超大模型上仍敢开 MTP 的原因：边际开销被压到了可以接受的范围，不会把本就紧张的显存吃穿。

两种接法有个共同的关键点：MTP 头只在训练时存在。推理主路径仍然是老老实实的单 token 预测，这些额外的头要么被直接丢弃，要么被复用来做投机解码。

```python
# 串行 MTP：D 个深度，每个深度在前一步基础上再预测一位
h = backbone(tokens)                        # 主干隐状态 [B, T, d]
loss = ce(shared_head(h), shift(tokens, 1)) # 深度 0：标准 NTP

for k in range(1, D + 1):
    # 关键：拼接上一深度隐状态 + 第 t+k 个真实 token 的 embedding，两者都要先 norm
    x = concat(norm(h), norm(embed(shift(tokens, k + 1))))
    h = mtp_block[k](x)
    loss += lam * ce(shared_head(h), shift(tokens, k + 1))  # lam 远小于 1
```

输出头（unembedding）和主干共享，所以真正新增的参数只有那 D 个 block，代价很小。

## 一个改动，训练和推理双赢

训练这一侧，多预测一步等于给每个位置加了额外监督。模型被迫在隐状态里为更远的未来预留信息，表示学得更有前瞻性。DeepSeek 报告在代码、数学这类强规划任务上提升最明显，通用闲聊文本收益则有限——这符合直觉，越需要提前布局的任务，越吃这套密集信号。

值得强调的是，MTP 带来的不是单步"训练加速"——它每一步反而要多算几个头，单步更慢。它真正的价值在样本效率：同样的 token 预算下，模型见到的有效监督更多，收敛到同一水平所需的数据更少。在真实数据见底、靠合成数据硬撑的今天，这种"把每条数据榨得更干"的目标格外值钱。

推理这一侧的收益更妙。训练好的 MTP 头本身就是一个现成的草稿模型：它能一次性给出未来几个 token 的候选，主模型只需并行验证，命中就跳步，这就是 self-speculative decoding。别人要专门训练一个小 draft model 才能做的事，MTP 顺手白送，还不存在主从模型分布不一致的隐患。

具体能跳多少，取决于草稿的命中率。MTP 头预测的 token 若和主模型逐个验证一致，就一次性接受多个；一旦某位不一致，就从该位截断、回退到普通解码。强结构文本里连续几个 token 高度可预测，命中率高、跳得远；自由发挥的文本命中率低，加速自然打折。这也是为什么 MTP 的推理红利高度依赖任务类型。

| 维度 | 标准 NTP | 并行多头 MTP | 串行 MTP（DeepSeek-V3） |
|---|---|---|---|
| 每位置监督 | 1 个 | n 个（相互独立） | D 个（有因果链） |
| 新增参数 | 无 | n 个输出头 | D 个 block（头共享） |
| 预测间耦合 | — | 弱 | 强 |
| 推理可复用 | 否 | 可做草稿 | 原生 self-spec |

## 和 Medusa、EAGLE 是一回事吗

容易混。Medusa、EAGLE 这类是纯推理期的方案：拿一个已经训练好的模型，事后额外接几个轻量头或小网络专门做草稿，主模型权重一动不动，只为加速服务。它们解决的是"怎么让现成模型跑得更快"这个工程问题。

MTP 不一样，它从预训练阶段就把多步预测写进了损失函数，首要目的是把模型本身训得更好，加速只是顺带的红利。换句话说，Medusa 是给成品装涡轮，MTP 是在出厂设计里就留了涡轮接口。两者甚至能叠加：用 MTP 训出来的模型再接 EAGLE 式草稿头，往往比从零加草稿更有效，因为模型早已习惯为未来留表示。

## 真正上手时会踩的坑

辅助权重 lambda 是第一个坑。MTP 是辅助目标，不是主角，系数设大了会反过来挤占主 NTP，导致主任务掉点。DeepSeek 用的是远小于 1、并随深度衰减的小系数：越往后的预测越不可靠，权重就越低。

深度 D 不要贪多。绝大部分收益来自 t+2 这一步，再往后信噪比快速下降，显存和计算却是线性往上涨。务实的做法是从 D=1 起步，确认有收益再谨慎加。还有个隐蔽的坑：串行块里隐状态和 token embedding 的尺度不一致，忘了各自 norm，loss 就是不降。

最后别忘了 MTP 头的身份。它默认只服务训练，推理若不做投机解码就该剔除，别稀里糊涂把它算进线上服务的显存预算。也别指望它替代真正的 draft model 包打天下——它的加速在强结构任务上明显，自由文本上有限。还要留意评测口径：看 MTP 的收益应盯主头在下游任务上的表现，而不是去比那几个辅助头自己的 loss，它们天生就该比主头差，拿来横评毫无意义。

踩坑清单：

- lambda 设太大 → 主任务掉点，务必远小于 1 且可随深度衰减
- D 贪多 → 显存线性涨而 t+3 之后几乎无增益，先从 D=1 起步
- 串行块忘了 norm → 隐状态与 embedding 尺度不匹配，loss 卡住不降
- 把 MTP 头当永久结构 → 不做投机解码时记得剔除，省显存
- 指望它当通用加速 → 强规划任务才明显，自由文本提升有限

一句话收尾：MTP 不换目标，只是在 NTP 之外顺手捡起本该免费的监督信号和草稿能力——训练更密，推理更快，代价不过是几个随时可丢的头。

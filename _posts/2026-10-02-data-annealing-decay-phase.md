你训练一个 LLM,大部分人盯着总数据配比——code、网页、数学各占多少。但真正拉开模型能力的,往往是最后那 5%-10% token 的"退火阶段"(annealing / decay phase)。LLaMA-3.1、OLMo-2、MiniCPM 的技术报告都专门写了这一段,它不是调参细节,而是一个独立的训练策略。

## 退火阶段到底是什么

退火指的是:主体预训练用海量但质量参差的数据跑完,当学习率进入衰减段时,你把数据分布切换成一小批高质量、高信号的语料——精选 code、数学推理、教科书级文本、甚至少量指令数据。模型在 LR 快速下降时"定型",这批数据的权重被放大得异常明显。

它和"数据配比"是两码事。配比管的是整个训练的平均成分,退火管的是时间维度上的最后一公里。同样的 1.5T token,前面怎么配是一回事,最后 100B 喂什么、按什么节奏降 LR 是另一回事,后者对 benchmark 的边际影响大得离谱。

一张表把主训练和退火的差别摆清楚:

| 维度 | 主训练 / stable 段 | 退火 / decay 段 |
|------|------------------|----------------|
| 数据量 | 90%+ token | 最后 5%-10% |
| 数据质量 | 海量、参差 | 精选、高信号 |
| 学习率 | 恒定高 LR | 快速衰减到近 0 |
| 目标 | 建立通用表征 | 淬炼下游能力 |
| 主要风险 | loss spike | 数据污染、能力回退 |

还要和两个近义词划清界限。continued pretraining 是在训好的 base 上用新领域语料继续跑,通常要重新 warmup LR,目标是注入领域知识;退火不重启 LR,只是原流程内部的衰减收尾。mid-training 则是预训练和 SFT 之间一切中间阶段的统称,退火是其中最经典、最被验证过的一种。

有多夸张?MiniCPM 的报告里,仅仅把退火阶段换成高质量配方,多个 benchmark 就能涨好几个点,成本却只是整条训练的零头。这也是为什么现在小团队复现强模型,第一个抄的往往不是架构,而是别人的退火配方。

## 退火数据该往里塞什么

核心原则是"高信号密度":单位 token 能教给模型最多可泛化能力的语料。实践中三类最稳:经过严格过滤的 code、带完整推导的数学题解、以及结构清晰的知识密集文本(百科、教材、论文)。网页垃圾在这个阶段要坚决砍掉。

一个常见误区是把退火当成"偷偷做 SFT"。你可以掺少量指令格式数据(几个百分点),让模型提前适应对话结构,但主体仍应是预训练式的自然文本。掺太多指令数据会让 base model 过早带上对齐腔,后续 SFT 反而更难调。

下面是一个参考配方(按 token 占比),给你一个起点而不是标准答案:

```text
退火阶段(最后 ~8% token)数据配比参考
---------------------------------------
精选 code        30%   # 去重、过编译、带注释
数学/推理        25%   # 带 step-by-step 推导
知识密集文本     25%   # 教材/百科/论文
高质量网页       12%   # 只留 top 质量分位
指令格式数据      8%   # 轻掺,提前适应对话
```

这些高质量语料从哪来?通常不是现找,而是把主训练用过的数据重新过一遍更严的质量分类器,只留 top 分位;code 要能过编译、数学要答案可验证。换句话说,退火桶是你整个数据管线里标准最苛刻的那一档,宁缺毋滥。

别迷信具体数字。不同 base、不同目标榜单,最优配方差很多。真正要抄的是方法论:把质量分位卡到最高、把污染风险压到最低、把每一类的占比当成可调旋钮,而不是照搬别人那张表就上。

## 和 WSD 学习率调度怎么配合

退火之所以叫退火,是因为它天然绑定学习率衰减。主流的 WSD(Warmup-Stable-Decay)调度就是为它设计的:稳定段用恒定高 LR 跑海量数据,到 decay 段 LR 快速下降,同时切换到退火数据。LR 高时模型可塑,LR 降到底时能力被"淬火"固定。

为什么"高质量数据放最后"比"均匀铺满全程"更划算?直觉是 LR 高时模型在大步探索,喂什么都会被后面覆盖掉;LR 低时每一步更新都接近最终权重,这时的数据分布几乎直接写进模型。把最贵的语料留到这一刻,边际收益最高。

关键是两条曲线要对齐。数据切换点应落在 decay 段的起点附近。切太早,高质量数据在高 LR 下被后续普通数据冲淡;切太晚,LR 已经很低,模型学不进新分布,退火就白做了。decay 步数一般占总步数的 10%-20%,太短消化不了、太长浪费算力。

举个具体的数:假设总训练 1.2T token、decay 段占 15%,那就是约 180B token 走退火。这 180B 别一刀切恒定配比,实践里常再做一层渐变——越接近训练末尾,高质量和指令数据占比越高,让模型在 LR 最低时吃到最干净的信号。

## 怎么在小模型上把配方调对

退火配方不该在目标规模上试错,一次几十万美元的训练你赔不起。标准做法是在 1B 以下的小模型上跑代理实验(proxy run):固定主训练 checkpoint,只变退火数据配方和衰减长度,看哪组在验证集上涨得最稳。

小模型的结论不会 100% 迁移到大模型,但相对排序通常保留——配方 A 比配方 B 好,这个结论往往跨规模成立。你要的不是绝对分数,而是"哪个配方更优"的方向性信号,这足够帮你在正式训练前砍掉大半烂方案。

一个实用技巧是复用主训练的中间 checkpoint 做分叉:从同一个 stable 段终点拉出多个分支,各自退火,横向对比。这样省去重复跑主训练的成本,一天就能扫完五六组配方,再把胜出的那组放大到目标规模。

退火跑完也别急着庆祝,先做消融:拿退火前的 base 和退火后的模型在同一批 benchmark 上并排评。只看涨幅不够,还要盯有没有能力回退——某些任务涨、另一些悄悄掉,是配方偏科的典型信号。评测务必用退火数据之外的 held-out 集,否则分数涨了也可能只是记住了答案。

## 实战清单与翻车点

退火最大的隐患是数据污染。你往里塞的高质量语料极容易混进 benchmark 测试集——教材、题解、竞赛题正是评测集的来源。退火阶段的污染放大效应比主训练强得多,因为这批数据权重高、离评测近,务必做 n-gram 去重比对。

退火前记得存一个 checkpoint。这是有风险的一步,配方不对可能让某些能力不升反降。留着退火前的 base,你才能回滚重试,而不是从头再跑 1T token。

实战踩坑清单:

- 退火数据没对训练集/测试集做去重,benchmark 虚高,上线原形毕露
- 指令数据掺超过 10%,base model 带上对齐腔,SFT 空间被压缩
- 数据切换点和 LR decay 起点没对齐,高质量语料被白白浪费
- 衰减步数拍脑袋定,没在小模型上扫过长度
- 退火前不存 checkpoint,配方翻车只能从头再来
- 把退火当成 SFT 替代品,跳过后续对齐流程

一句话总结:预训练的上限由你喂了多少 token 决定,但模型最终能打什么榜,常常是最后 10% 的 token 和那段 LR 衰减一起淬出来的。

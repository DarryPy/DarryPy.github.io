你可能花了大量时间调 LoRA 超参、纠结 optimizer，却对一个根本性问题视而不见：**你的数据干净吗？**

Chinchilla 定律告诉我们，模型性能对数据量的敏感度远超参数量。但"数据量"的前提是数据质量——一份含 30% 噪声的语料，真实有效规模只有 70%，剩下的不但没帮助，还可能主动拖后腿。

本文拆解预训练数据过滤的四个核心环节，附可直接参考的实战配置。

## 第一关：去重 — 重复数据是隐性毒药

Common Crawl 的原始爬取结果里，大量网页存在跨域转载、镜像站和模板页。若不去重，模型会对这些片段产生过拟合，泛化能力直线下滑。

去重分两层：

**精确去重**：对每个文档取 SHA-256 或 MD5，哈希碰撞即删。速度快，但只能处理完全相同的副本。

**模糊去重（MinHash LSH）**：
```python
from datasketch import MinHash, MinHashLSH

def get_minhash(text: str, num_perm=128) -> MinHash:
    m = MinHash(num_perm=num_perm)
    for word in text.lower().split():
        m.update(word.encode("utf8"))
    return m

lsh = MinHashLSH(threshold=0.8, num_perm=128)
# threshold=0.8 表示 80% Jaccard 相似度以上视为重复
```

MinHash 能捕捉"改了几个词的转载"。Jaccard 阈值建议 0.7–0.85，太低会误删有价值的近似文档，太高漏掉大量软重复。

实测数据：C4 去重后语料缩减约 30%，但下游评测分数反而提升——这就是噪声的代价。

## 第二关：质量打分 — 让高质量文档说了算

原始 web 数据包含广告、导航菜单、SEO 垃圾文和乱码。常用的质量过滤信号：

| 信号 | 做法 | 阈值参考 |
|------|------|----------|
| 字符多样度 | unique_chars / total_chars | < 0.1 过滤 |
| 平均行长 | 总字符 / 行数 | < 10 或 > 10000 过滤 |
| 数字/字母比 | digit_count / alpha_count | > 0.4 过滤（可能是数据表/验证码） |
| 标点密度 | punct_count / token_count | > 0.25 过滤（可能是爬虫乱码） |
| 困惑度过滤 | 用 KenLM 小模型打分 | top 30% 高困惑度删除 |

困惑度过滤是最有效也最被低估的一招。用目标语言（如中文）的 5-gram KenLM 给每条文档打分，丢弃困惑度最高的 20–30%，等于自动过滤掉混杂语种、机器生成垃圾和乱码文档。

Falcon 数据集（RefinedWeb）就是靠严格的 trafilatura 抽取 + 质量规则，在更少的数据量上超越了 LLaMA-1。

## 第三关：毒性与隐私过滤 — 不过滤等着翻车

毒性内容不只是道德问题，更是工程问题——含大量仇恨言论的预训练会让模型更难被 RLHF 对齐，你需要多花 3–5 倍的人工标注预算来修复。

**毒性过滤**：用 fasttext 训练一个二分类器（toxic/clean），对每条文档打分。阈值不要太激进，0.7+ 才删，避免误删正当的社会议题讨论。

**个人信息（PII）过滤**：
```python
import re

PII_PATTERNS = [
    r"\b\d{11}\b",                          # 11位手机号
    r"\b\d{18}[0-9X]\b",                    # 身份证
    r"\b[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Z]{2,}\b",  # 邮件
    r"\b(?:\d{1,3}\.){3}\d{1,3}\b",        # IP 地址
]

def has_pii(text: str) -> bool:
    return any(re.search(p, text) for p in PII_PATTERNS)
```

这层过滤能显著降低模型生成真实个人信息的风险，也是合规要求的最低线。

## 第四关：配比策略 — 配方比原料更重要

过滤完成后，你面对的是不同来源、不同质量、不同领域的语料池。怎么混是门学问。

**领域过采样**：代码、书籍、学术论文这类高密度语料，即便数量少也应提高权重。GPT-4 技术报告隐约暗示书籍语料被上采样了约 10 倍。

**动态权重调整**：训练中途检测各源的 validation loss，对 loss 下降慢的来源减权。DoReMi 和 RegMix 都是这个思路的正式化版本。

推荐的起点配比（中文通用 LLM）：

```
网页语料     45%   # 去重 + 质量过滤后
书籍/文献    20%   # 上采样
代码         15%   # 提升推理能力
百科         10%   # 知识密度高
其他          10%  # 新闻、问答、对话
```

这不是银弹，要根据目标任务迭代调整。

## 踩坑清单

- **不要用原始 Common Crawl 直接训练**：没过滤过的 WARC 文件噪声率 > 60%，会严重压低效果。
- **去重先做精确再做模糊**，顺序反了浪费大量 MinHash 计算。
- **困惑度阈值别一刀切**：代码和数学本来就困惑度高，要分领域设阈值，否则会把宝贵的代码数据误删。
- **留验证集时要做时间切分**，不能随机采样——否则训练集和验证集的网页互相转载，你的 loss 会虚假地好看。
- **记录每一步过滤后的文档数**，否则复现时你不知道到底丢了什么。

数据过滤没有终点，只有"当前最优"。多数团队在这里欠的债，最终都得用更多对齐成本来还。
